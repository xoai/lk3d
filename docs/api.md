# API

```js
// a page: one script tag, the global LK3D (https://unpkg.com/lk3d@0.1.0/dist/lk3d.min.js, or a copy of dist/lk3d.min.js)
<script src="https://unpkg.com/lk3d@0.1.0/dist/lk3d.min.js"></script>;
// or a module
import LK3D, { mount, build, defaults, locales } from 'lk3d';
```

## mount(el, scene, options) → figure

Draws `scene` ([format](scene-format.md)) in the element `el`, with the built-in controls under it, and returns the
figure. For screen readers the canvas is an application (`role="application"`, described as a 3D model) named by
the scene's `alt` and described by what its keys do; what the reader chooses is said aloud (a polite live region:
the part's name and note, not what the pointer passes over), and every named part is listed, with its note, in a
list after the figure (not drawn on the page). Every handle is also a range input for the keyboard and screen
readers.

| Option                     | Default                  | Meaning                                                                                                                                                                                                                                                                   |
| -------------------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `info`, `infoIdle`         |                          | an element that shows the name and note of the part pointed at (only `b i em strong sub sup br` kept as HTML; the rest as text); what it says when none is                                                                                                                |
| `controls`                 | `true`                   | `false`: no built-in buttons (build your own with the figure's methods)                                                                                                                                                                                                   |
| `steps`                    | `controls`               | `false`: no panel for the scene's [guided steps](#guided-steps) under the figure (the page goes through them with `step()`)                                                                                                                                               |
| `step`                     | `0`                      | the step the figure starts at, by its place (from 0) or id; `-1`: before the first, the figure at its own start                                                                                                                                                           |
| `onStep(index, step)`      |                          | the reader went to another step with the panel's Back or Next (not the page's own `step()`)                                                                                                                                                                               |
| `style`                    | scene's, else `'pen'`    | the first look: `'pen'`, `'studio'` or `'ink'`                                                                                                                                                                                                                            |
| `theme`                    | scene's, else none       | the colours: `'light'`, `'dark'`, `'blueprint'`, `'sepia'`, `'auto'`, or a name added to `LK3D.themes`                                                                                                                                                                    |
| `labels`                   | `'auto'`                 | `'auto'` (on hover and when taken apart), `'all'`, `'none'`, or `[ids or groups]`: exactly those parts' labels                                                                                                                                                            |
| `transparent`              | `false`                  | `true`: nothing painted behind the model, in any look and theme (the canvas is clear; the theme's lines, solids and words still apply)                                                                                                                                    |
| `onPick(part)`             |                          | a part chosen by the reader (a tap, a click, a handle reached by Tab), or `null` when they let it go; a part is `{ id, name, note, group, min, max, center, triangleCount }` (its box's corners and middle in the scene)                                                  |
| `onHover(part)`            |                          | the part under the pointer as it moves onto one, or `null` as it moves off                                                                                                                                                                                                |
| `onHandle(id, value)`      |                          | a handle moved by the reader (not by the page's own `handle(id).set`)                                                                                                                                                                                                     |
| `handleText(id, value)`    |                          | what a screen reader says for a handle's value, e.g. `` `d = ${v} cm` ``                                                                                                                                                                                                  |
| `locale`, `strings`        | `'en'`                   | the language of the built-in words (`'en'`, `'vi'`, or any key of `LK3D.locales`); single words changed                                                                                                                                                                   |
| `buttonClass`              | lk3d's own               | the page's class for the built-in buttons                                                                                                                                                                                                                                 |
| `quality`                  | 1 (0.6 on small screens) | shape detail                                                                                                                                                                                                                                                              |
| `maxTriangles`             | 1 million or 10 million  | the most triangles the scene may have here: 1 million where memory is small (a screen under 700 px a side, or `navigator.deviceMemory` under 4 GB), else 10 million (2 million a part); over it, the scene is built coarser, down to a quarter of `quality`, else refused |
| `validate`                 | the engine's guard       | the full rules to check the scene by before it is built: `validate` from `lk3d/validate`; its first problem is thrown                                                                                                                                                     |
| `maxDpr`, `adaptive`, `ao` | 3, `true`, `true`        | the highest pixel density; lowering resolution while frames run late; crease shading                                                                                                                                                                                      |
| `force2d`, `webgl1`        |                          | for testing: the Canvas 2D fallback, or WebGL 1                                                                                                                                                                                                                           |

`LK3D.defaults` (`locale`, `strings`, `buttonClass`) sets these for every figure on a page.

**A scene that cannot be drawn** is refused before anything is built or drawn: `mount` throws an `Error` whose message
names the place, e.g. `lk3d: parts[2].shapes[0].lathe: has 5000 items; at most 1000`, or `lk3d: the scene would have at
least 3200000 triangles; the limit is 1 million`. By default the engine's own guard checks what building needs (plain
data: finite numbers, no loops, at most 32 deep, lists of at most 100 000 items and profiles or outlines of at most
1000 points, a million values in all; parts and shapes as lists of objects), and building names the shape it could not
build and counts triangles against `maxTriangles`, before and while it builds. The full rules (the
[schema](scene-format.md#validating), the cross-references) are not in the script, to keep it small: give them as
`validate` for a scene you did not write. They take a few milliseconds even on large scenes.

```js
import { validate } from 'lk3d/validate';
try {
  LK3D.mount(el, sceneFromSomeoneElse, { validate });
} catch (e) {
  el.textContent = e.message; // "lk3d: parts[2].handle.moves: moves \"rotor\", which is no part or group"
}
```

## Guided steps

A scene's `steps` ([format](scene-format.md)) explain the figure in order. Each has its words (a `title`, `text`, or
both) and the state of the figure while it is shown: where the camera goes (`view`, `focus`), how far apart
(`explode`), the cut (`cut`, `section`), see-through (`xray`), which `labels` show, parts hidden (`hide`), a part
chosen (`select`), the motions' values (`motion`) and which play (`play`).

```json
"steps": [
  { "id": "whole", "title": "An AC generator", "text": "Turn the rotor and a current lights the lamp.", "view": "home" },
  { "id": "rotor", "title": "The rotor", "text": "Cut open: magnets turn inside the coils.", "cut": true,
    "labels": ["magnet-n", "magnet-s"], "view": { "yaw": -20, "pitch": 16 } },
  { "id": "circuit", "title": "The circuit", "text": "Each half-turn turns the current round.",
    "focus": ["circuit"], "select": "filament" }
]
```

The figure starts at the first step (or `opts.step`), and a panel under it shows the step's words with Back and Next;
its words are said aloud as the reader comes to each. Going to a step sets everything it describes, and what it leaves
out goes back to the figure's start: put together, not cut, see-through off, labels as `opts.labels` says, nothing
hidden or chosen, every motion at its start and stopped. So a step is the same picture however the reader came to it,
by Next, by Back or straight from the page. The camera is the exception: it moves only when the step gives a `view`
or parts to `focus` on, so a step that only changes what is shown leaves the reader's view alone. `focus` frames the
parts as they will be once the step has taken them apart, from the view's angles if it gives them. The explode, the
cut and the camera glide there together (at once when the reader asked for reduced motion). In between, the reader
explores as usual; the next step sets its own state again.

A page can go through the steps itself instead, say as the reader scrolls through its own text, with the panel left
out:

```js
const fig = LK3D.mount(el, scene, { steps: false });
for (const section of document.querySelectorAll('[data-step]'))
  new IntersectionObserver(([entry]) => entry.isIntersecting && fig.step(section.dataset.step), {
    threshold: 0.6,
  }).observe(section);
```

`lk3d check` checks that what each step names exists (parts and groups, motions within their range), that a labelled
part has a label and is not hidden by the same step, and that a step cuts only where the scene offers a cut; `lk3d
render` draws each step as a picture of its own (`--poses steps`, with the others by default when the scene has
steps).

## Driving a figure from a timeline

A page whose every frame is a function of its own time `t` (a video renderer that seeks to any time and takes a
picture) stops the figure's clock and sets everything for `t` itself:

```js
const fig = LK3D.mount(el, scene, { controls: false, adaptive: false, transparent: true, theme: 'dark' });
await fig.ready;
LK3D.clock.speed = 0; // the figure's time is the page's
fig.flow({ path, speed: 0.6 });
function seek(t /* seconds */) {
  LK3D.clock.set(t * 1000); // flows, streams and particles along paths are where their speed puts them at t
  fig.set({
    camera: { yaw: -35 + 10 * t, pitch: 18, zoom: 1 + t / 20 }, // placed at once, not glided
    explode: Math.min(1, t / 4),
    cut: Math.min(1, t / 6), // the section plane sweeping in
    labels: t > 2 ? ['rotor'] : [],
    move: { cover: [0, Math.min(1, t / 3), 0] },
  });
  fig.drawNow(); // drawn before seek returns
  const at = fig.project([0, 0.2, 0], 'rotor'); // [x, y] for the page's own caption, pinned to the rotor (or null)
}
```

With the clock stopped, a flow, a stream or particles along a path are placed for the clock's time: what their speed
carries them in that time, so one time is always one picture, seeking forwards or back. When their speed (or the
figure's `timeScale`) changes, they go on from where they were last drawn at the new speed: a page that changes a speed
along its timeline seeks in order (as an export does) to get the same picture every time. [Liquids pouring and gases
settling](fluids.md) are moved on by each step of the clock forwards, never back. Tweens (`view`, `explode(v)`, a
motion's `play()`) run on the same clock; a timeline sets their values instead (`camera`, `explode`, `motion`).

## The reader's controls

| Reader does                                 | The figure                                                                                                                                                                                                                       |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| drags (mouse, finger or pen)                | turns, with momentum (none under reduced motion); on a part with a handle, moves the handle. A finger moved up or down scrolls the page until the figure has been touched (a touch outside it gives the page back its scrolling) |
| Shift-drags, or drags with the right button | pans                                                                                                                                                                                                                             |
| pinches (two fingers)                       | zooms towards the fingers' middle                                                                                                                                                                                                |
| turns the wheel                             | zooms towards the pointer, only with Ctrl held or once the figure has been clicked (a click outside it lets the page scroll again)                                                                                               |
| taps or clicks a part                       | chooses it (`onPick`): lit, its note shown                                                                                                                                                                                       |
| presses the arrow keys (canvas focused)     | turns (left and right round the vertical, up and down)                                                                                                                                                                           |
| presses `+` or `=`, `-`                     | zooms in, out                                                                                                                                                                                                                    |
| presses Page Down, Page Up (canvas focused) | chooses the next, the previous named part on show (as a click: `onPick`, lit, its note shown and said); Escape lets it go                                                                                                        |
| Tabs to a handle                            | reaches its range input: arrow keys, Page Up and Page Down move it                                                                                                                                                               |

Zoom stops at `view.minZoom` of the distance that fits the whole model (0.02: 50 times closer) and at three times that
distance going out. The built-in controls under the figure (each where the scene has a use for it) take it apart (a
slider and a button), cut it open, see through, show all labels, go round the looks, glide to the views (front, side,
top, home), and give each named motion a slider and a play button.

## The command line

```sh
npx lk3d check scene.json [--json]
npx lk3d render scene.json [--looks pen,ink,studio] [--poses rest,apart,cut] [--theme NAME] [--ortho] [--width 640] [--out DIR]
npx lk3d export scene.json [out.glb] [--animate] [--motion id=value,…]
```

- `check`: the format (`lk3d/validate`), then the geometry (`lk3d/lint`), with the scene's size; exit code 1 on any
  problem. `--json` prints `{ summary, problems }` instead, failures included.
- `render`: one PNG per look and pose (pen and ink, at rest, apart and cut, by default), drawn by the engine in a
  headless browser; `--theme` a colour theme, `--ortho` the orthographic camera, `--width` in pixels (64 to 4096),
  `--out` the folder (the working one). It needs Playwright, and draws with the engine built from `src/` as it runs
  (in a checkout of the repository, after `npm install`; an installed package without esbuild uses the
  `dist/lk3d.min.js` it shipped with).
- `export`: the scene as glTF 2.0 binary (to `out.glb`, else the scene's own name with `.glb`), posed at the motions'
  starts (or as `--motion` sets them), each motion an animation with `--animate`.

A model given as a file (`"file": "heart.glb"`) is read from beside the scene, from one folder up, or from where lk3d
runs. Flags go anywhere on the line.

## Theme

Without a [theme](looks-and-materials.md#themes) (which sets them on the stage itself), the figure's colours and
lettering come from CSS variables a page sets on `:root` or any element around the figure:
`--lk3d-ink`, `--lk3d-paper`, `--lk3d-muted`, `--lk3d-accent` (focus), `--lk3d-warn` (the scale note),
`--lk3d-highlight` (pressed buttons), `--lk3d-font` (labels in the drawn look).
